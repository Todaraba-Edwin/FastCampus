## 1 원리를 모르는 개발자는 뛰어난 개발자가 아니다

### (1) 일단 작동만 하는 코드 vs 제대로 작동하는 코드

- 뛰어난 개발자 = 제대로 작동하는 프로그램을 만드는 사람
  - 코드가 어떤 과정을 거쳐 실행되는지 명확하고 자세하게 설명 가능
- 잘못 공부한 사례
  - "부동소수점 연산은 틀릴 수 있다"만 암기 → 왜 틀리는지 질문하면 답변 불가
  - 원리(2진수 표현 → 근사값 → 오차) 기준으로 설명할 수 있어야 함
- 실무 대응
  - 금액 계산: 정수(원 단위) 또는 Decimal 사용
  - 비교: 값을 직접 비교하지 않고 허용 오차 사용 (예: `Math.abs(a - b) < 1e-9`)

### (2) 프로그램의 원리를 이해하기 위한 컴퓨터 과학

- 사례: 아래 코드의 결과 (Python / JavaScript 동일)

  ```python
  print(0.1 + 0.2)        # 0.30000000000000004
  ```

  ```javascript
  console.log(0.1 + 0.2); // 0.30000000000000004
  ```

  - 기대값 0.3과 결과 불일치 → 원인을 설명할 수 있어야 함
  - 원인: 부동소수점을 2진수로 저장, 0.1은 2진수로 정확히 표현 불가 (무한 소수)
  - 저장 과정에서 근사값으로 바뀌어 덧셈 결과에 오차 발생
  - 올바른 답변
    - 부동소수점: 실수를 2진수 근사값으로 저장
    - 0.1처럼 정확히 표현되지 않는 값 → 연산 오차 발생

## 2 컴퓨터 과학 지도 그리기: 기술 면접에 대비하고 싶다면

### (1) 컴퓨터 과학은 키워드 암기 과목이 아니다

- 강조: CS 지식은 암기가 아닌 이해와 적용의 영역
- 목적: 실무 개발의 재료(개념, 원리)를 얼마나 보유했는지 확인
  - 개념 → 원리 → 실무 적용 순으로 연결할 수 있는지 점검

- 사례 추가: `https://minchul.net` 입력 → 웹 페이지 표시 과정
  - 1단계 URL 해석: 프로토콜(https), 도메인(minchul.net), 경로(/) 분리
  - 2단계 DNS 조회: 도메인 → IP 주소 (브라우저 → OS → 로컬 DNS → 상위 DNS 순 캐시 확인)
  - 3단계 TCP 연결: 3-way handshake (SYN → SYN-ACK → ACK), 서버 443 포트
  - 4단계 TLS 핸드셰이크: 서버 인증서 검증, 세션 키 합의 → 암호화 채널 수립
  - 5단계 HTTP 요청: `GET /` 전송 (Host, Cookie, User-Agent 등 헤더 포함)
  - 6단계 서버 처리: 리버스 프록시 → 웹 애플리케이션 → 응답 생성
  - 7단계 HTTP 응답: 상태 코드(200 등)와 HTML 수신, 3xx면 리다이렉트 후 재요청
  - 8단계 렌더링: HTML → DOM, CSS → CSSOM 결합 → 렌더 트리 → 레이아웃 → 페인트
  - 9단계 리소스 로딩: 이미지·CSS·JS 추가 요청, JS 실행 후 화면 완성
  - 10단계 연결 정리: keep-alive로 재사용 또는 FIN으로 종료

### (2) 책에서 다루는 내용: 대다수 직군에서 강조되는 지식

```bash
# 책에서 다루는 내용: 대다수 직군에서 강조되는 지식
- 본서
  ㄴ 1 컴퓨터 구조
     ㄴ 큰 그림
        ㄴ 컴퓨터 구조의 큰 그림
     ㄴ 컴퓨터가 이해하는 정보
        ㄴ 데이터
        ㄴ 명령어
     ㄴ 컴퓨터의 핵심 부품
        ㄴ CPU
        ㄴ 메모리와 캐시 메모리
        ㄴ 보조기억장치
        ㄴ 입출력장치
  ㄴ 2 운영체제
     ㄴ 큰 그림
        ㄴ 운영체제의 역할
        ㄴ 운영체제 지도
        ㄴ 시스템 콜과 이중 모드
     ㄴ 주요 개념
        ㄴ 프로세스와 스레드
        ㄴ 동기화와 교착 상태
        ㄴ CPU 스케줄링
        ㄴ 가상 메모리
        ㄴ 파일 시스템
  ㄴ 3 자료구조
     ㄴ 큰 그림
        ㄴ 자료구조와 알고리즘
        ㄴ 시간 복잡도와 공간 복잡도
        ㄴ 자료구조 지도
     ㄴ 주요 자료구조
        ㄴ 배열과 연결 리스트
        ㄴ 스택과 큐
        ㄴ 해시 테이블
        ㄴ 트리
        ㄴ 그래프
  ㄴ 4 네트워크
     ㄴ 큰 그림
        ㄴ 네트워크의 기본 구조
        ㄴ 두 호스트가 패킷을 주고받는 과정
        ㄴ 네트워크 지도
     ㄴ 주요 개념
        ㄴ 물리 계층과 데이터 링크 계층: 이더넷, 유무선 매체, NIC, 허브와 스위치
        ㄴ 네트워크 계층 IP: 목적, 주소 구조, 공인/사설 IP, 할당, ICMP, ARP
        ㄴ 전송 계층 TCP와 UDP: 특징, 연결과 종료, 상태 관리
        ㄴ 응용 계층 HTTP: DNS와 URL, 메시지 구조, 메서드와 상태 코드, 헤더
        ㄴ 응용 계층 HTTP 응용: 쿠키, 캐시, 콘텐츠 협상, HTTPS
        ㄴ 프록시와 안정적인 트래픽: 포워드/리버스 프록시, 로드 밸런싱, Nginx
  ㄴ 5 데이터베이스
     ㄴ 큰 그림
        ㄴ 데이터베이스와 DBMS
        ㄴ 파일 대신 데이터베이스를 쓰는 이유
        ㄴ 저장 단위와 트랜잭션
        ㄴ 데이터베이스 지도
     ㄴ 주요 개념
        ㄴ RDBMS 기본: 테이블, 관계, 무결성 제약 조건
        ㄴ SQL: DDL, DML, TCL
        ㄴ 효율적 쿼리: 서브 쿼리와 조인, 뷰, 인덱스
        ㄴ 설계: ER 다이어그램, 정규화
        ㄴ NoSQL: MongoDB, Redis
```
