## 3 동기화와 교착 상태

### (1) 동기화 기법

- 공유 자원: 여러 프로세스/스레드가 함께 접근하는 변수, 파일, 장치 등
- 임계 구역: 공유 자원에 접근하는 코드 영역
  - 둘 이상이 동시에 진입 시 경쟁 조건(race condition) 발생 → 데이터 불일치
  - 한 번에 하나만 진입하도록 보장 필요 → 동기화의 목적
- 레이스 컨디션(race condition): 실행 순서(타이밍)에 따라 결과가 달라지는 상태
  - 원인: `count++`가 원자적(atomic)이지 않고 3단계(읽기 → 증가 → 쓰기)로 나뉨
  - 사례: 공유 변수 `count = 0`에 스레드 A, B가 각각 `count++` 1회 실행
    - 기대값: 2 / 실제값: 1 (갱신 손실, lost update)

```bash
# count++ 의 내부 동작 (기계어 수준)
# 1. LOAD  : 메모리의 count 를 레지스터로 읽기
# 2. ADD   : 레지스터 값 + 1
# 3. STORE : 레지스터 값을 메모리 count 에 쓰기

# [문제 상황] 시간 흐름 ↓ (초기값 count = 0)
#
#   시간   스레드 A              스레드 B              메모리 count
#   ----   ------------------    ------------------    ------------
#   t1     LOAD  (reg_A = 0)                           0
#   t2     ← 문맥 교환 →         LOAD  (reg_B = 0)     0   # B 도 옛날 값 0 을 읽음
#   t3                           ADD   (reg_B = 1)     0
#   t4                           STORE (count = 1)     1
#   t5     ADD   (reg_A = 1)                           1
#   t6     STORE (count = 1)                           1   # A 가 B 의 결과를 덮어씀
#
#   → 2번 증가시켰는데 결과는 1 (B 의 갱신이 사라짐)

# [해결 후] 임계 구역을 한 번에 한 스레드만 진입
#
#   스레드 A  : [ LOAD → ADD → STORE ]
#   스레드 B  :                        (대기) [ LOAD → ADD → STORE ]
#   count     : 0 ───────────────→ 1 ─────────────────────────→ 2   # 항상 2
```

#### 동기화 기법

> 동기화의 두 가지 목적
>
> - 실행 순서 제어: 프로세스/스레드가 정해진 순서대로 실행되도록 조율
>   - 예: 생산자가 데이터를 쓴 뒤에야 소비자가 읽기 (A 완료 → B 시작)
>   - 세마포어의 `wait`/`signal`로 선행 작업 완료를 알림
> - 상호 배제(mutual exclusion): 공유 자원(임계 구역)에 동시에 하나만 접근
>   - 예: `count++`를 한 스레드씩 수행 → 레이스 컨디션 방지
>   - 뮤텍스 락, 이진 세마포어로 구현

1. 뮤텍스 락(mutex lock): 임계 구역에 한 번에 하나만 진입시키는 잠금
   - 진입 전 `lock()` 획득 → 사용 후 `unlock()` 반납
   - 락 보유자만 해제 가능 (소유권 존재)
   - 이진 상태(잠김/열림)
2. 세마포어(semaphore): 정수 카운터로 공유 자원 접근 수를 제어
   - 진입 전 `wait(P)` 획득 → 사용 후 `signal(V)` 반납
     - `wait(P)`: 카운터 -1, 0 이하면 대기
     - `signal(V)`: 카운터 +1, 대기자 깨움
   - 이진 세마포어(binary semaphore)
     - 카운터가 0 또는 1 → 자원 1개에 대한 접근 제어
     - 뮤텍스와 유사하게 상호 배제 구현
     - 소유권 없음 → 다른 스레드가 `signal` 가능 (실행 순서 제어에도 활용)
   - 카운팅 세마포어(counting semaphore)
     - 카운터 N → 공유 자원 N개, 최대 N개 동시 접근 허용
     - `wait` 1회마다 카운터 -1 (허용 수 소진) / 0이면 이후 호출자 대기
     - `signal` 1회마다 카운터 +1 (허용 수 복구) → 대기자 진입
   - 카운팅 세마포어 흐름 이해 (프린터 3대 사례)
     - 사용 시작: `wait` 반복 → 카운터 3 → 2 → 1 → 0 (자리가 하나씩 줄어듦)
     - 만석: 카운터 0 → 새 요청은 대기열에서 기다림
     - 사용 종료: `signal` → 카운터 +1 (자리 하나 복구)
     - 재개: 복구된 자리에 대기자 1명 진입 → 다시 `wait` 효과로 카운터 -1
     - 정리: `wait` = 자리 차지(-1) / `signal` = 자리 반납(+1)
   - 뮤텍스 vs 세마포어: 공유 자원의 개수 차이
     - 뮤텍스: 공유 자원이 1개 → 한 번에 하나만 접근
     - 세마포어: 공유 자원이 복수(N개) → 카운터 값만큼 동시 접근 허용
     - 사례: 프린터 3대, 커넥션 풀 10개, 주차장 5자리
       - 남은 자원 수 = 카운터 / 자원 반납 시 `signal` → 대기자 진입
3. 조건 변수와 모니터
   - 조건 변수(condition variable): 특정 조건이 충족될 때까지 대기하고, 충족 시 깨우는 도구
     - `wait()`: 조건 불충족 시 락을 반납하고 대기 큐에서 대기
     - `signal()`(notify): 조건 충족을 알려 대기 중인 스레드를 깨움
     - 주 용도: 실행 순서 제어 (예: 버퍼가 비어 있으면 소비자 대기)
   - 모니터(monitor): 공유 자원 + 접근 함수를 하나로 묶어 상호 배제를 자동 보장
     - 한 번에 하나의 스레드만 모니터 내부 함수 실행 (락 직접 관리 불필요)
     - 모니터 안에서 조건 변수를 함께 사용 → 상호 배제 + 실행 순서 제어
     - 사례: Java `synchronized` + `wait()`/`notify()`

> 스레드 안전(thread safe)

- 도구가 아닌 성질(규칙): 여러 스레드가 동시에 호출해도 결과가 항상 올바른 상태
- 위 1~3은 스레드 안전을 달성하는 수단
- 그 외 달성 방법
  - 불변 객체(immutable object): 공유는 하되 쓰기를 없앰
    - 생성 후 상태(필드 값)가 바뀌지 않는 객체 → 읽기만 가능, 레이스 컨디션 불가
    - 수정 필요 시 기존 객체를 고치지 않고 새 객체를 만들어 교체 (예: Java `String`)
    - 조건: 필드 `final` / setter 없음 / 내부 가변 객체는 복사본으로만 제공
    - 장점: 락 불필요, 안전한 공유 / 단점: 변경마다 새 객체 생성 비용
  - 스레드 로컬(thread local): 공유 자체를 피함
    - 스레드마다 변수 사본을 따로 보유 (분리 단위: 프로세서가 아닌 스레드)
    - 공유 자원이 아니므로 경쟁 조건 없음 → 락 불필요
    - 사례: 요청별 사용자 정보 보관 (Java `ThreadLocal`, Python `threading.local`)
    - 한계: 스레드 간 결과를 합치려면 다시 공유 필요 / 스레드 풀 사용 시 값 초기화 필요
  - 원자적 연산(atomic): 쪼개지지 않는 연산 사용

### (2) 교착 상태

- 교착 상태(deadlock): 둘 이상의 프로세스/스레드가 서로 상대가 가진 자원을 기다리며 영원히 멈춘 상태
  - 어느 쪽도 자원을 내놓지 않음 → 외부 개입 없이는 해소 불가
  - 동기화와의 관계: 동기화를 잘못 쓸 때 생기는 부작용
    - 레이스 컨디션: 동기화 부족 때문에 발생
    - 교착 상태: 동기화(락 사용) 때문에 발생
- 사례: 락 2개(L1, L2)를 서로 반대 순서로 획득

```bash
# 시간 흐름 ↓
#
#   스레드 A                  스레드 B
#   ---------------------     ---------------------
#   L1 획득
#                             L2 획득
#   L2 요청 → 대기 (B 보유)
#                             L1 요청 → 대기 (A 보유)
#
#   → A 는 B 의 L2 를, B 는 A 의 L1 을 기다림 → 둘 다 영원히 대기
```

- 발생 조건 4가지: 모두 동시에 성립해야 발생 → 하나만 깨도 예방 가능
  - 상호 배제: 자원을 한 번에 하나만 사용 가능
  - 점유와 대기: 자원을 쥔 채로 다른 자원을 추가로 기다림
  - 비선점: 다른 쪽이 쥔 자원을 강제로 빼앗을 수 없음
  - 원형 대기: 대기 관계가 A → B → … → A 고리를 이룸
- 해결 방향 (이어서 학습)
  - 예방: 4가지 조건 중 하나를 구조적으로 깨기
  - 회피: 자원 할당 전 안전한지 검사 (은행원 알고리즘)
  - 탐지 및 복구: 발생 후 찾아서 프로세스 종료/자원 회수
  - 무시: 드물다고 보고 방치 (타조 알고리즘)
