## 첫째, Naive RAG의 문제점과 Advanced RAG의 등장

### (1) Naive RAG란?

#### 개요
- **정의**: 사용자 질문 → 검색 → 결과 문서 → LLM 답변생성의 단순한 파이프라인
- **목적**: 외부 지식 기반을 활용하여 LLM의 할루시네이션 감소 및 최신 정보 반영

#### 상세 설명

- **기본 개념**
  - 사용자의 질문을 받아 벡터 임베딩으로 변환
  - 벡터 DB에서 의미적으로 유사한 문서 검색
  - 검색된 문서들을 LLM의 컨텍스트로 제공
  - LLM이 검색된 정보를 기반으로 답변 생성
  - 외부 지식 활용으로 최신 정보 반영 가능

- **동작 프로세스**
  - 전처리: 문서 로드 → 단순 청킹 → 임베딩 생성 → 벡터 DB 저장
  - 실행: 쿼리 → 벡터 검색 → 상위 K개 문서 → 컨텍스트 전달 → 답변 생성
  - 간단하고 직관적인 구조로 빠른 구현 가능

- **주요 한계**
  - 문서 파싱 미흡: 텍스트만 추출, 표/이미지/구조 정보 손실
  - 청킹 문제: 고정 길이로 분할하며 의미 있는 경계 무시
  - 검색 부정확: 벡터 유사도 기반만으로 관련성 정확도 낮음
  - 쿼리 모호성: 사용자 원본 질문의 모호함을 해결 불가
  - 순위 문제: 관련 정보가 무관련 정보에 묻혀 순위 하락

### (2) Advanced RAG 개요

#### 정의
- Naive RAG의 한계를 극복하기 위해 전처리, 검색, 재평가 단계를 고도화한 RAG 방식

#### 핵심 전략 (4가지)
- **(1) 사용자 질문 구체화**: 모호한 질문을 명확하고 다양하게 변형
- **(2) 문서파싱**: 표, 이미지, 구조를 포함한 의미론적 전처리
- **(3) 구조적 청킹**: 문서의 논리적 경계를 보존하며 분할
- **(4) 리랭킹**: 초기 검색 결과를 정밀하게 재평가

#### 전략별 상세 설명

- **사용자 질문 구체화**
  - 원본 질문의 모호성을 제거하여 검색 정확도 향상
  - Query Expansion: 동의어와 관련어 추가로 검색 범위 확대
  - Query Refinement: 질문을 더 명확하고 구체화된 형태로 재작성
  - Pseudo-Relevance Feedback: 초기 검색 결과로 질문 개선 후 재검색
  - Query Decomposition: 복합 질문을 여러 단순 질문으로 분해
  - 다각도 검색으로 더 많은 관련 문서 확보
  - 최종적으로 검색 재현율(recall) 및 정밀도(precision) 개선

- **문서파싱**
  - 원본 문서의 모든 정보를 의미론적으로 이해하고 추출
  - DLA (Document Layout Analysis): 페이지 레이아웃 및 구조 분석
  - TSR (Table Structure Recognition): 표의 행/열 관계 자동 인식
  - LLM 기반 OCR: 다양한 문서 형식에서 정확한 텍스트 추출
  - 메타데이터 생성: 각 요소의 의미와 관계 정보 포함
  - 이미지-텍스트 연관성 파악으로 완전한 의미 이해
  - 청킹 단계에 최적화된 구조화 데이터 생성

- **구조적 청킹**
  - 고정 길이 분할의 문맥 손상 문제 해결
  - 계층적 청킹: 제목 레벨(H1, H2, H3)에 따라 섹션 단위로 분할
  - 마크다운 기반 청킹: 구조화된 형식으로 변환하여 의미 보존
  - DOM 기반 청킹: HTML/XML 구조를 활용한 자연스러운 분할
  - 스마트 청킹: 청크 경계의 문맥을 고려한 동적 분할
  - 각 청크가 독립적으로 의미를 가질 수 있도록 최적화
  - 검색 정확도 및 추론 정확도 20~30% 향상

- **리랭킹**
  - 벡터 검색만으로는 부족한 정밀도 문제 해결
  - Bi-encoder: 초기 검색 단계에서 빠른 임베딩 기반 후보 추출
  - Cross-encoder: 추출된 각 후보를 쿼리와 함께 평가하여 정확한 관련성 점수 부여
  - Two-Stage Retrieval: 재현율(Bi-encoder) + 정밀도(Cross-encoder) 조합
  - Lost in the Middle 현상 완화로 관련 정보 상위 순위 보장
  - 실전 패턴: 빠른 상위 N개 추출 후 정밀한 리랭킹으로 효율성 극대화
  - 24~48% 성능 향상 (TREC 데이터셋 기준)

#### 성능 개선
- 검색 정확도 및 LLM 답변 품질 **20~48% 향상**
- 특히 복잡한 쿼리와 대규모 문서 환경에서 효과 극대화

## 셋째, Advanced RAG의 확장으로서의 Modular RAG

### (1) 세 가지 RAG 패러다임 비교

#### Naive RAG의 특징
- 단순 선형 파이프라인: 질문 → 검색 → 결과
- 벡터 검색만으로 문서 추출, 추가 처리 없음
- 구현이 간단하고 빠르지만 정확도 한계 존재
- 고정된 단일 검색 방식, 유연성 부족

#### Advanced RAG의 특징
- 검색 전/후 처리로 정확도 향상
- 질문 구체화, 문서파싱, 구조적 청킹, 리랭킹 등 4가지 전략 적용
- 각 단계가 연결되어 있으나 파이프라인 구조 유지
- 성능 20~48% 향상 가능

#### Modular RAG의 특징
- 각 단계를 독립적인 모듈로 설계
- 사용 사례에 따라 필요한 모듈만 조합하여 사용 가능
- 모듈 간 의존성 감소로 높은 유연성 확보
- 각 모듈을 독립적으로 최적화 및 개선 가능
- 복잡한 질문과 대규모 시스템에서 확장성 우수
