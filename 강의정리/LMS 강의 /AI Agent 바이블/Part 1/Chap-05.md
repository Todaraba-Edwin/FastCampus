## 첫째, Naive RAG의 문제점과 Advanced RAG의 등장

### Naive RAG란?

**정의**
- 사용자 질문 → 검색 → 결과 문서 → LLM 답변생성의 단순한 파이프라인
- 외부 지식 기반을 활용하여 LLM의 할루시네이션 감소 및 최신 정보 반영

**Naive RAG의 구조**
- 문서 로드 → 단순 청킹 → 임베딩 생성 → 벡터 DB 저장
- 사용자 쿼리 → 벡터 검색 → 상위 K개 문서 → LLM에 전달 → 답변 생성

**주요 한계**
- 문서 파싱 미흡: 텍스트만 추출, 표/이미지/구조 손실
- 청킹 문제: 고정 길이로 분할하며 의미 단절
- 검색 정확도: 벡터 검색만으로는 관련성 정확도 낮음
- 쿼리 문제: 사용자 원본 질문의 모호성 해결 불가

### Advanced RAG 개요

**정의**
- Naive RAG의 한계를 극복하기 위해 전처리, 검색, 재평가 단계를 고도화한 RAG 방식

**4가지 핵심 전략**
- **(1) 사용자 질문 구체화**: 모호한 질문을 명확하고 다양하게 변형
- **(2) 문서파싱**: 표, 이미지, 구조를 포함한 의미론적 전처리
- **(3) 구조적 청킹**: 문서의 논리적 경계를 보존하며 분할
- **(4) 리랭킹**: 초기 검색 결과를 정밀하게 재평가

**성능 개선**
- 검색 정확도 및 LLM 답변 품질 20~48% 향상

---

### (1) 사용자 질문 구체화

**등장이유**
- 원본 질문이 모호하면 검색 결과 부정확
- 질문 확장/구체화로 검색 정확도 개선

**내용**
- Query Expansion: 동의어/관련어 추가로 검색 범위 확대
- Query Refinement: 질문을 더 명확하고 구체화된 형태로 재작성
- Pseudo-Relevance Feedback: 초기 검색 결과로 질문 개선 후 재검색
- Query Decomposition: 복합 질문을 여러 단순 질문으로 분해

### (2) 문서파싱

**등장이유**
- 문서에서 단순 텍스트만 추출하면 표, 이미지, 레이아웃 정보 손실
- 비정형 문서의 의미론적 구조를 AI가 이해할 수 있도록 전처리 필요

**내용**
- DLA (Document Layout Analysis): 페이지 레이아웃 구조 분석
- TSR (Table Structure Recognition): 표의 행/열 구조 자동 인식
- LLM 기반 OCR: 문자 인식 + 의미론적 이해 결합
- 메타데이터 생성: 청킹 최적화를 위한 구조화된 데이터 생성

### (3) 구조적 청킹

**등장이유**
- 고정 토큰 길이로 단순 분할하면 문서의 논리적 경계 파괴로 문맥 손상
- 문서 구조를 보존하며 분할하면 검색 정확도 및 추론 정확도 20~30% 향상

**내용**
- 계층적 청킹: 제목 레벨(H1, H2, H3)에 따라 섹션 단위로 분할
- 마크다운 기반 청킹: PDF를 마크다운으로 변환하여 구조화된 형식 활용
- DOM 기반 청킹: HTML/XML의 DOM 구조에 따라 의미 있는 블록 단위 보존
- 스마트 청킹: 청크 경계의 문맥을 고려한 동적 분할

### (4) 리랭킹

**등장이유**
- 벡터 검색만으로는 관련 문서를 놓치거나 무관련 문서를 포함 ("Lost in the Middle" 현상)
- 이단계 검색으로 빠른 검색(재현율) + 정밀한 재평가(정밀도) 조합하면 24~48% 성능 향상

**내용**
- Bi-encoder: 초기 검색 단계에서 빠른 임베딩 기반 후보 추출
- Cross-encoder: 추출된 후보들을 재평가하여 정확한 관련성 점수 부여
- Two-Stage Retrieval: Bi-encoder(빠름) → Cross-encoder(정밀)의 이단계 파이프라인
- 실전 패턴: 빠른 상위 N개 추출 후 정밀한 리랭킹으로 최고의 효율성 달성
