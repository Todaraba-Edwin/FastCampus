## 첫째, 파인튜닝

### 파인튜닝의 정의와 목적

- 파인튜닝: LLM의 사고 방식이나 말투를 바꾸기 위해 수행
- LLM 등장 이후 환각현상 대응으로 등장한 기법
  - 사실이 아닌 정보를 신뢰도 높게 생성하는 환각현상 문제
  - 신뢰할 수 있는 도메인 데이터로 모델을 재학습
  - 특정 분야의 정확성과 신뢰도 향상

### 캐릭터 챗 성격/성향 조정 사례

- Zeta(한국 챗봇)를 예로 들면:
  - 특정 성격과 가치관을 학습시켜 일관된 응답 스타일 형성
  - 사용자와의 상호작용에서 캐릭터 정체성 유지
- 모델별 차이점 (파인튜닝의 결과)
  - GPT: 감성적 표현, 사용자 감정 공감에 초점
  - Claude: 사고적 분석, 논리적 설명에 초점
  - 같은 질문에 서로 다른 성격의 답변 생성

## 둘째, RAG의 정의와 목적

### RAG(Retrieval-Augmented Generation) 개요

- RAG: 외부 데이터를 검색하여 LLM의 응답을 보강하는 기법
- 파인튜닝과의 차이점
  - 파인튜닝: 모델 자체를 재학습하여 성격/성향 변경
  - RAG: 모델은 고정, 외부 지식베이스에서 정보를 검색하여 활용
- 사내 지식 챗봇의 기본 구조
  - 조직의 내부 문서, 매뉴얼, DB를 검색 가능하게 구축
  - 사용자 질문에 관련된 문서를 검색 후 답변 생성
  - 최신 정보와 조직 특화 지식 반영 가능

### 실무 사례

- 한국도로공사
  - 도로 관리, 유지보수 매뉴얼, 안전 규정 등을 지식베이스로 구축
  - 직원이 빠르게 관련 정보를 조회 가능
  - 일관되고 정확한 업무 수행 가능
- 한국수자원공사
  - 수자원 관리 정책, 댐 운영 매뉴얼, 환경 기준 등 저장
  - 현장 직원의 의사결정 지원
  - 문서 검색 시간 단축

### 간단한 RAG 구축 흐름

```mermaid
graph LR
    A["📄 도큐먼트<br/>문서 프로세싱"] --> B["🔢 인베딩<br/>벡터화"]
    B --> C["🔍 리트라이벌<br/>검색"]
    C --> D["⭐ 리랭킹<br/>순위 조정"]
    D --> E["🤖 LLMOps<br/>응답 생성"]
    E --> F["💬 최종 답변"]
```

- **도큐먼트 문서 프로세싱**
  - 사내 문서(PDF, 텍스트 등)를 수집하고 정제
  - 큰 문서를 의미있는 청크(Chunk)로 분할
  
- **인베딩(Embedding)**
  - 텍스트를 수치 벡터로 변환 (임베딩 모델 사용)
  - 의미상 유사한 문서들은 벡터 공간에서 가까워짐
  
- **리트라이벌(Retrieval)**
  - 사용자 질문을 인베딩한 후 벡터 DB에서 유사 문서 검색
  - 상위 K개의 관련 문서 추출
  
- **리랭킹(Reranking)**
  - 검색된 문서들의 순위를 재조정
  - 질문과의 관련도를 다시 평가하여 가장 적합한 문서를 우선배치
  
- **LLMOps**
  - 리랭킹된 문서들을 프롬프트와 함께 LLM에 전달
  - 검색된 정보를 바탕으로 최종 답변 생성
  - 사용자가 이해하기 쉬운 형태로 정보 종합

## 셋째, 장기작업 수행이 가능한 AI 에이전트

### 마누스(Manus)

- **장기작업 수행의 핵심**: 인간이 수행하기 어려운 반복적, 정밀한 작업을 자율적으로 실행
  - 긴 시간 동안 일관된 정확도 유지 (피로도 없음)
  - 복잡한 손동작 시퀀스를 기억하고 반복 실행 가능
  - 산업 현장의 조립, 검사, 수리 등 물리적 작업 자동화

- **컨텍스트 윈도우를 활용한 작업 지속성**
  - 사용자의 장기 지시사항을 메모리에 유지하며 단계별 수행
  - 작업 중간의 환경 변화에 적응하면서 원래 목표 달성
  - 작업 히스토리를 통해 수행한 작업 추적 및 검증

### 클로드코드(Claude Code)

- **장기작업 수행의 핵심**: 소프트웨어 개발의 전체 사이클을 자율적으로 관리
  - 프로젝트 생성부터 배포까지 수개월의 작업을 단계별로 진행
  - 파일 시스템 전체를 이해하고 일관성있게 코드 수정
  - 버그 수정, 기능 추가, 리팩토링을 연속으로 실행

- **상태 추적과 피드백 루프를 통한 작업 최적화**
  - 각 단계 완료 후 사용자에게 진행 상황 보고
  - 사용자 피드백이나 테스트 결과를 즉시 반영하여 작업 조정
  - 오류 발생 시 자동으로 원인 분석하고 재작업 수행
  - 장기 프로젝트에서도 초기 의도와 일관성 유지
